# D2 — протокол практической диагностики

**Статус:** готовность материалов к пилоту. Фактическое тестирование детей, реальные ответы и индивидуальные выводы **не получены**.

## Цель

Доказать в реальной сессии, что 5 вопросов на тему позволяют определить точный дефицит, возможную причину и следующее конкретное учебное действие. Пяти вопросов недостаточно для психометрической классификации; спорные результаты проверяем новыми вопросами.

## 1. Подготовка

1. Согласовать с родителем и ребёнком цель: диагностировать знания, не оценивать личность или интеллект; получить необходимое согласие на тестирование.
2. Взять анонимный `student_code`; фамилию, фотографию, контакты, полную дату рождения и иные персональные сведения **не помещать в GitHub**.
3. Определить `FOUNDATION` или `SAT_BRIDGE`, школьный класс и язык инструкций, не помещая их в публичную форму с идентификаторами ребёнка.
4. Выбрать темы в [Math blueprint](MATH_BLUEPRINT.md) / [English blueprint](ENGLISH_BLUEPRINT.md).
5. Копировать на отдельный лист **только student questions** из соответствующего файла, полностью исключив блоки `<details> ... </details>`. PDF/печать не должны случайно раскрыть teacher key. Для пилота возможна очная работа родителя/преподавателя с закрытым ключом.
6. Не применять высокий timed pressure на Foundation; режим `observational` на старте для всех.

## 2. Последовательность занятия

- **0–3 мин**: объяснить правила без обучения решению тестовых вопросов; показать, как отмечать A/B/C/D.
- **3–30 мин**: 2–5 тем (10–25 вопросов) в зависимости от подготовки/возраста. Начало и конец фиксировать **по теме**, паузы отдельно.
- **После каждой темы**: фиксировать ответы до разбора и не менять их после показа ключа.
- **После сессии**: раскрыть ключ и объяснение, уточнить причины ошибок, предложить ребёнку объяснить решение собственными словами.
- **Результат**: карта пробелов, маршрут из имеющихся уроков, 2-недельный план, назначенный контроль на других задачах через 7–14 дней.

## 3. Обязательные поля протокола

[Пустая CSV-форма](templates/session_capture.csv) для локального копирования. **Реальные заполненные формы не коммитить**.

- Student code, session/attempt/topic IDs, question bank revision.
- `started_at`, `finished_at` c часовым поясом, `paused_seconds`; целевой показатель `active_seconds` вычисляется отдельно.
- Ответы A/B/C/D Q1..Q5 (или пустая строка для неотвеченного, отличать от непройденной темы).
- Подсказки `hint_used`, тест завершён `SUBMITTED / INCOMPLETE / NOT_ASSESSED`.
- Ошибки и объяснение преподавателя после фиксации ответов.

## 4. Правила первичной оценки

| Верно из 5 | Категория | Следующее действие |
|---|---|---|
| 0, 1, 2 | GAP | Восстановить prerequisite, пройти конкретный урок, повторить **новыми** вопросами |
| 3 | VERIFY | 2–3 дополнительных вопроса, проверить характер ошибки |
| 4, 5 | PROVISIONAL_SECURE | Новые transfer / trap задачи, перенос в смешанный набор |
| Нет предъявленных вопросов | NOT_ASSESSED | Не записывать как 0 баллов |
| Прерванная попытка | INCOMPLETE | Завершить позднее или назначить отдельную попытку |

**Любая подсказка снижает уверенность, а не обязательно математическую точность.** `5/5` после подсказки = `ASSISTED`, не окончательный mastery.

## 5. Пост-разбор причин

Для каждой ошибки поставить один основной код и при необходимости вторичный. В Math используйте существующие `R/M/A/L/C/G/T/K` и признак prerequisite `PR`; в английском — `GRAM/VOC/READ/CONTEXT/PUNC/RUSH`. Код должен подтверждаться объяснением ребёнка или конкретным неверным ходом, а не автоматически выводиться из буквы варианта.

Если ошибка на математике только в английской формулировке, дать аналогичную задачу на русском языке, сохранив математическую структуру. Это помогает не смешивать два разных дефицита.

## 6. Отчёт и учебная стратегия

Сформировать [пустой шаблон отчёта](templates/gap_report_template.md). Описывать не обобщённые оценки, а:
- точный навык;
- правильные и неправильные задачи;
- evidence и вероятную причину;
- необходимые prerequisite;
- конкретный урок/тренировку (ссылка на существующий файл в репозитории);
- новые диагностические задания на подтверждение;
- контрольную дату и условия успеха.

Приоритет: критические prerequisites → широкие ошибки базовых навыков → высокозначимые SAT темы → скорость/отработка ловушек.

## 7. Критерии приемки D2 (пока НЕ выполнены)

- [ ] По меньшей мере один реальный добровольный пилот с согласием родителя (данные не в Git).
- [ ] Записаны start/end/pause по каждой проведённой теме.
- [ ] Зафиксированы первичные ответы до разбора, не исправлялись задним числом.
- [ ] Человеком проверены спорные формулировки и отвлекающие варианты.
- [ ] Создан персональный отчёт с конкретными навыками, не единственным общим процентом.
- [ ] Проверено, что рекомендации соответствуют ошибкам и prerequisites.
- [ ] Пилот выявил реальные сценарии для изменения банка; corrections оформляются отдельными revisions.
- [ ] Через 7–14 дней получено повторное evidence на новых задачах.
- [ ] Отсутствует утверждение о сертифицированном уровне CEFR или официальном SAT score.

## 8. Типовые ограничения

- Пять MC-заданий допускают угадывание; категория `PROVISIONAL_SECURE` не равна длительному освоению.
- При непонимании текста проверять язык отдельно от вычислений.
- Младшим детям важнее понимание, чем таймер.
- Данные ребёнка — приватны; публичный репозиторий содержит только обезличенные примеры и пустые формы.
