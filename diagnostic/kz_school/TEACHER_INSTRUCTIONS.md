# Қазақ мектебі — бірінші диагностиканы өткізу жөніндегі нұсқаулық / инструкция преподавателю

## До начала

- Используйте только `print/grade6_student_kk.md` или `print/grade9_student_kk.md` по выбранному классу, **не** файл `teacher`.
- Ученик может взять вариант с русскоязычной математикой, если это соответствует домашнему учебному языку, но не переключайте язык посреди одного диагностического блока без фиксации.
- В каждой теме 5 вопросов; фиксируйте старт/финиш/паузы. Тайминг — наблюдение, а не скоростной экзамен.
- Получите согласие родителя и разъясните ребёнку, что можно остановиться. Никаких заполненных персональных бланков в GitHub.

## Два уровня диагностического разбора

**1. Математика / Математикалық дағды.** Может ли ребёнок сам объяснить, почему он выбрал действие, и решить новую задачу того же типа на казахском? Если нет — вероятен пробел в понятии, вычислениях или prerequisite.

**2. SAT English language / тілдік дағды.** Если математика решается на казахском, но ученик не понимает аналогичную новую английскую формулировку, это отдельный `LANGUAGE_CONDITION` gap. Нельзя писать `ALGEBRA_GAP` только потому, что английский текст не прочитан.

**Ағылшын грамматикасы / английская грамматика.** Предложения остаются на английском. Не переводите сами задания перед выбором ответа — иначе вы измерите способность пользоваться подсказкой, а не понимание английского.

## Не ставить диагноз по букве

| Пример | Возможные причины | Как подтвердить |
|---|---|---|
| −15 − (−6) неверно | минус перед скобкой / операция с отрицательными | попросить объяснить переход к сложению |
| 1/2 + 1/4 неверно | общие знаменатели / сложение числителей | попросить нарисовать доли или объяснить знаменатель |
| 20% рост + 20% снижение = 0 | процент от разных оснований | попросить найти сумму после первого шага |
| `does he speaks` | двойная маркировка 3-го лица | спросить, что происходит с глаголом после does |
| `is working` vs `works` | длительность против привычки | попросить объяснить `usually` vs `right now` |

Не объявляйте причину подтверждённой, пока ребёнок не объяснит своё решение. Правильная буква при случайном угадывании тоже не подтверждает понимание.

## После одной темы

1. Сохраните первичный ответ, до показа ключа.
2. Отметьте `GAP` (0–2/5), `VERIFY` (3/5), `PROVISIONAL_SECURE` (4–5/5), `ASSISTED` или `NOT_ASSESSED`.
3. Дайте 1–3 **новые задачи** до урока для независимого подтверждения, если оцениваете качество теста.
4. Только после этого объясните материал по закрытому ключу `teacher_kk_ru.md` и назначьте prerequisite.
5. Через 7–14 дней используйте новые задания для измерения прогресса, **не повторяйте тот же лист**.

## Критерии первой рабочей проверки

- В обоих классах сохраняются ответы и время по каждому блоку.
- Ученик видит только student-вариант.
- Причины ошибок записаны с доказательством, а не выводятся автоматически из буквы ответа.
- Русский и казахский варианты одной задачи — **не независимые формы теста**.
- Отчёты хранятся приватно; в GitHub можно публиковать только агрегированные обезличенные технические результаты.
- Полный 225-вопросный банк, будущие unseen-формы и определение уровня CEFR требуют независимой профессиональной проверки.
